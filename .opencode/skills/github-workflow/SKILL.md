# Skill: GitHub Workflow

Guidelines for common GitHub operations in this repository.

## Branching

- One branch per focused change: `feature/<name>`, `fix/<name>`, or `chore/<name>`.
- Keep branches short-lived; merge via PR when the team requires review.

## Pull Requests

- Title: short, imperative (`Add X`, `Fix Y`).
- Body: what changed, why, and how to verify.
- Link related issues with `Fixes #N`.

## Commits

- Conventional style preferred: `feat:`, `fix:`, `docs:`, `chore:`.
- One logical change per commit.

## Review

- Address review feedback with a new commit (don't amend shared commits).
